# 05 复盘与下一步

## 最难的问题：证据存在不等于结论可靠
最初的引用检查只能证明片段存在于文档，不能证明模型的自由文本结论被片段支持。团队因此选择保守的原文抽取式答案，最终发布内容来自已验证引用，保留模型负责选择动作、证据和结束状态的职责。这个取舍降低了答案流畅性，也不能替代通用的语义相关性检查，但能直接阻止“真引用、假结论”的关键缺陷。

第二个难点是内容更新与冲突：只更新正文会让旧 facts 标注失效；若只丢弃标注却继续把“没有检测到冲突”当成“一致”，仍会误答。实现把失效数量传递到执行上下文；相关证据标注过期或同主题多文档缺少可比较事实时，选择查证或追问。版本新旧不表示优先级。

## 发现与修复
| 问题 | 实际调整 | 验证材料 |
|---|---|---|
| 正文变化后继续使用旧 facts | 对原文、quote、value 做一致性检查，传递 discarded_fact_count，阻止未经核实的确定回答 | tests/test_retrieval.py、tests/test_runtime.py |
| 搜索找到多份制度，只读一份就作答 | 同主题未读候选阻止 answered | tests/test_runtime.py |
| 引用正确但模型编造期限 | 最终 answer/gaps 按状态规范化，回答抽取自引用 | tests/test_runtime.py |
| “火星半径多少”被当成模糊指代 | 缩小 Mock 的指代追问触发范围，无资料时补搜后停止 | tests/test_runtime.py |
| 年假年度天数与申请提前期混淆 | 针对合成领域的明确事实维度增加缺口检查 | examples/outputs/、tests/test_runtime.py |
| Windows 子进程中文编码不一致 | CLI、评估入口及测试子进程显式使用 UTF-8 | tests/test_cli.py |
| 自定义场景 ID 影响输出路径 | 限制安全文件名并验证项目路径边界 | tests/test_evaluation.py |

最终结果、准确测试数量和实际失败情况以 [03-evaluation.md](03-evaluation.md) 为准。

## 学习与工程取舍
- 先约定 Model/Tool/Runtime 合同，才能让开发与独立测试同时推进；测试必须真正经过目标分支，不能因前置校验失败而空过。
- 先确认题目要验证的决策循环，再选框架。大型框架提供的完整运行时并非本题必需，轻量实现更容易复现和审查。
- 原文、版本、资料缺口、执行预算和错误都应成为明确的数据结构；仅有一段看起来合理的回答不足以验收。
- 关键缺陷要用内容替换和恶意模型输出复现，而不只测试固定正常问句。
- 词面同义词改善只在两个手工查询上得到证明；不能外推为真实企业检索效果。

## 后续工作（按优先级）
1. 已按授权进行DeepSeek真实评测并保存失败与修复记录，见 `10-live-evaluation.md`。后续需要独立留出集、多次重复实验、token用量与费用采集，不能把当前固定案例的一轮通过率当成泛化能力。
2. 引入独立、未参与规则编写的中文改写与冲突测试集，覆盖否定、适用部门、政策废止、优先级和不同主题切换。
3. 在更大语料上对比词面检索、混合检索与重排；保留引用核验与不确定状态，而不是只提高召回。
4. 需要生产服务时增加文档权限、来源审核、版本变更流程、运行审计和观测；当前 CLI 不具备生产服务边界。
5. 用户提供目标仓库后再提交 GitHub URL 与最终 commit SHA；本轮按确认范围保留为本地项目。

## 真实评测的追加收获

离线传输stub未覆盖模型自发提出多个read的情形，首次真实评测因此只有9/13通过。按原模型顺序仅执行首个合法只读动作、下轮重新决策后，再以独立协议测试和真实复测验证。此次还明确了资料缺口与执行未完成的状态边界。整个修复没有改变案例预期或增加默认步数，首轮失败始终保留。
