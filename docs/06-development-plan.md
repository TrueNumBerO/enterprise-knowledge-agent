# 开发计划

## 目标与验收
交付企业知识问答 CLI：模型驱动 search/read/finish 循环、可验证引用、资料冲突查证、资料外拒答、改写问句、上下文追问和工具失败处理。所有工具返回均进入下一次模型决策。最多 8 步，达到上限明确 incomplete。

## 分工及阶段
1. 项目经理：题目拆分、公开架构调研、冻结接口、规范文档、集成验收。
2. 开发 agent：真实模型适配、显式离线模式、执行循环、引用防护、CLI。
3. 检索与资料 agent：版本化合成知识库、检索/读取工具、冲突和不足场景。
4. 测试 agent：独立验收测试、内容替换测试、实际运行记录与回归。

依赖顺序：接口合同 → 并行实现与测试设计 → 联调 → 缺陷反馈与修复 → 回归、文档及交付。先完成核心闭环，再扩展边界测试；不引入无必要的 Web UI、分布式 Runtime 或向量服务。

## 完成标准
- tests 可执行，六个题目验收点都有实际运行输出/trace。
- 至少三组正常、资料不足、工具失败输入输出，并包含多条由工具观察导致差异的路径。
- 引用必须匹配本次读取原文；冲突不按日期或严格程度擅自裁决。
- docs/01 至 05、README、依赖和环境示例齐全。
- 如无模型凭据，清楚报告 live 未验证，不把 Mock 当成真实模型验收。
- 如无指定 GitHub 仓库/认证，仅交付本地可提交项目，不伪造远程 URL 或 SHA。

## 续办验收补充
资料缺口检查需覆盖含“申请”的年度天数问法和上下文追问；历史只用于补足主题，不可覆盖当前问题的事实维度。已知事实冲突的双方引用应展示实际矛盾内容，不能只附两份文档的共有句子。非法模型动作或历史结构应受控失败，不向 CLI 泄露堆栈。
