# 01 需求与验收

## 用户与目标
员工需要查询公司制度或产品常见问题，答案必须能回到具体版本的原文。知识库为本项目专门编写的合成数据，不包含真实公司隐私。

输入为问题与可选对话历史；输出为回答、文档 ID、版本日期、原文引用、资料缺口、任务状态与实际执行 trace。交付方式为 Python CLI。

## 本轮边界
用户于 2026-11-02 确认先完成本地项目、离线测试和真实模型接入入口。2026-11-03 用户在本地.env填写密钥并授权真实DeepSeek评测，真实运行记录与修复前后结果另行保存。GitHub仓库与远程提交仍未提供或执行，密钥不进入提交材料。

## 验收矩阵
| 需求 | 可观察成功标准 |
|---|---|
| 明确答案 | 无冲突资料下回答包含支持结论的原文与版本 |
| 文档冲突 | 同主题 30 天与 15 天并列引用，补查，仍无优先级则请求确认，不自行裁决 |
| 资料外问题 | 补充搜索仍无证据时列缺口，不编造答案 |
| 改写后的相似问题 | 合成领域内同义表达仍能找到同一文档，记录检索改进对比 |
| 上下文追问 | 当前问题结合历史消解指代；历史回答不是可引用事实 |
| 工具失败 | 结构化失败进入下一轮观察；可恢复时由模型选重试，不可恢复时明确失败 |
| 内容替换 | 替换原文后重新运行，答案或状态随证据改变，不读取陈旧事实标注 |
| 执行上限 | 最多设定步数，耗尽明确 incomplete；不得假报成功 |
| 引用可靠 | 只引用本次成功读取的文档，ID、日期、逐字片段完全匹配 |
| 模型决策循环 | live 模式每轮调用外部模型，工具结果回送后由模型决定下一动作 |

## 非目标及限制
不建设 Web 页面、分布式服务、权限系统或向量数据库。本项目不代表生产企业知识系统；有限语料和人工同义词不能证明开放域召回。离线规则模型只能证明流程与保护逻辑，不能证明真实模型的语义理解或 ReAct 效果。
