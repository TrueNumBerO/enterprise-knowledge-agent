# 合成资料说明

全部文档仅用于工程演示，无真实员工信息。邮箱使用 `.invalid` 保留域。

- `knowledge.json`：D01 与 D02 分别写明 30 天和 15 天，未提供可裁决冲突的适用范围或优先级。日期新旧不代表优先级。D06 明确记录资料缺口。
- `single_policy.json`：只有 D01、D04、D05；用于验证只有一条报销期限依据时可据文作答。
- `retrieval-evaluation.json`：手工构造的两个查询，比较同一检索器关闭和开启同义词的 Recall@2。样本极小，只说明该改写的改善。

## 文档约束

顶层为 `documents` 数组；每条有唯一 `doc_id`、ISO 日期 `version_date`、`title`、`content`、`topic` 及可选 `facts` 数组。知识库大小不超过 2 MB。`facts` 是维护者对合成资料的人工结构化标注，不是模型提取，也不是可无条件信任的另一份知识库。

读取时只保留 `quote` 逐字存在于 `content` 且 `value` 存在于 `quote` 的事实项。修改正文后，不匹配的旧标注立即丢弃，并在读取返回的 `discarded_fact_count` 中统计。这只是结构一致性验证，不能理解否定、范围和隐含条件的任意变化；更新资料时仍须人工审核并同步标注。业务答案必须引用实际读取的原文。

## 检索与读取

检索使用中文双字词面、英文词、文档频率权重与人工同义词簇；显式业务主题用于约束候选，避免“年假提前多久”仅因“多久”召回报销冲突。返回摘要只是发现候选的工具输出，不能直接作引用。

`KnowledgeBase(path, use_synonyms=False)` 可关闭同义词，用于小样本词面基线比较。`search` 的 `total` 是筛选后总候选数，`returned` 是截取后数量；`limit` 支持 1–20，默认 5。`read(doc_id)` 返回完整原文的独立副本。

`fail_searches=N` / `fail_reads=N` 表示实例的前 N 次对应调用返回可重试的合成故障，之后恢复。无效参数与未知文档是不可重试错误；此功能不代表对真实基础设施故障的性能验证。
